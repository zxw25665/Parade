# “游行”：去中心化局域网加密协作软件设计书 v2

> Version: `v0.2.0-libp2p` · Last updated: 2026-06-08
> 本版基于 v0.1 (gRPC 架构) 重写，全面反映 libp2p 迁移后的运行时现实。

## 简介

本软件旨在消灭协作的“最后一公里”：明明在同一个局域网下，内部网络畅通无阻且高速，但我们却没有一个方便好用的本地化协作方案。

* 用U盘？每次只能一台设备读取数据，需要物理意义上的走来走去，且若文件有了更新整个过程还要再来一次。
* 用社交软件？且不说我们是否信任大公司掌握我们的数据，为什么需要把文件先送到他们的服务器、再从服务器发回来？这显得非常多余，更不用说“14天删除”和“文件小于1GB”的限制了。
* 用SMB等共享协议？配置起来非常不便，需要分发密码，且性能并不稳定。况且，这只能由一个人作为中心，如果一个团队之间需要互相传递数据，显然不能每个人各自设立一个SMB服务、给其余的所有人各自配置一个密码。

“游行”旨在解决这些问题。软件的目标是提供一个易于安装部署和操作的一站式协作平台。具体功能特点如下：

* 完全去中心化 - 没有必须的任何硬件投资，不需要为了一场小组作业租用云服务器或购入软路由。
* 端到端加密 & 本地磁盘加密 - 阻止有心人窃取你的信息，无论是在本地还是在云端。
* 易于使用的通信协作 - 创建你的队伍，与成员私聊或组建包含任意成员的群聊，就像微信一样简单。
* 高性能文件共享 - 每个人都是参与者。选定你的共享目录，控制成员权限，点击共享即可，从此忘掉SMB的账号密码和繁琐操作。成员可以从本地拉取文件或上传到本地，无论文件大小多少，如丝般顺滑。

## 整体系统架构

系统由五大引擎（EventBus、Crypto、Database、Logger、File）和两大业务层（Network、App）构成，按依赖方向单向组装。

```
main.go — 依赖组装入口
  │
  ├── 1. eventbus.New()          内存 pub/sub，每 topic 独立 goroutine
  ├── 2. crypto.NewEngine()      Curve25519 + Argon2id 身份与三层加密
  ├── 3. db.NewSQLiteDB()        WAL 模式 SQLite，纯 Go 无 CGO
  ├── 4. logger.NewLogBroker()   异步 JSONL 环形缓冲日志
  ├── 5. file.NewEngine()        虚拟文件树 + 2MB 分块 + BLAKE3 + 断点续传
  │       .WithDatabase(db).WithEventBus(bus).WithLogger(log)
  ├── 6. network.NewLibp2pEngine(bus, cry, log)
  │       .AttachFileEngine(file) (后置注入打破循环依赖)
  ├── 7. app.NewWailsUI()        Wails runtime.EventsEmit 包装
  └── 8. app.NewApp(bus, cry, db, net, file, ui, log)
         → wails.Run({ Bind: [appInstance] })
```

**网络模型对比 (v0.1 → v0.2)**:

| 维度 | v0.1 (gRPC) | v0.2 (libp2p) |
|------|-------------|---------------|
| 传输协议 | gRPC over HTTP/2 | TCP + Noise + Yamux |
| 身份认证 | 应用层握手 | Noise 传输层 (ed25519 从 Curve25519 派生) |
| 群聊 | gRPC bidi streaming | GossipSub (pub/sub) |
| 私聊 | bidi stream 多路复用 | 专用流 `/parade/private-chat/1.0.0` |
| 文件传输 | gRPC server streaming (4328) | libp2p 流 `/parade/file-download/1.0.0` (同 4327) |
| 发现 | mDNS (hashicorp/mdns) | libp2p 内置发现 + TCP 4328 识别 |
| 端口 | 2 (4327 控制 + 4328 数据) | 1 (4327 全部多路复用，4328 为辅助识别) |
| 连接模型 | N×(N-1) gRPC 连接 | GossipSub O(N) + per-peer TCP |

### 前端交互

“游行”的前端致力于提供媲美原生桌面应用的流畅体验，完全屏蔽底层分布式网络的复杂性。

* 技术栈: Vue 3.5 (Composition API + `<script setup>`) + Vite 6 + vue-i18n
* 状态管理: **无 Pinia**，采用 `reactive()` 模块级单例 composable (useStore / useEvents / useLogStore)，避免过度抽象
* 路由: **无 vue-router**，固定三栏 CSS Grid 布局，由状态驱动视图切换
* IPC: Wails v2 自动生成 Go↔JS 桥接 (`window.go.app.App.*`)，`useBackend.js` 统一封装所有 30 个绑定方法并自动记录调用日志
* 国际化: en + zh，`localStorage['parade-locale']` 持久化

**三栏布局**:

```
┌──────────────────────────────────────────────────┐
│  Header (状态栏, 语言切换)                        │
├──────────┬───────────────────────┬───────────────┤

│ (身份 /  │  (ChatPanel — 消息     │  (节点列表 /  │
│  队伍 /  │   输入与展示)          │   文件浏览 /  │
│  会话列表)│                       │   下载列表 /  │
│          │                       │   日志面板)   │

```

* 网络拓扑与会话（左侧）: `IdentityPanel` → `TeamPanel` → `ConversationList` → `PeerStatus`，动态显示局域网内在线成员，通过绿/灰圆点标识心跳状态
* 消息流（中部）: 严格按照 HLC 字符串字典序排序的消息流，支持群聊/私聊模式切换
* 虚拟文件树 + 下载 + 日志（右侧）: `FileBrowser`（本地/远程模式） + `DownloadList` + `LogPanel`

### 文件共享

在文件共享层面，“游行”抛弃了传统的中心化文件服务器，转而采用“分布式多中心与按需拉取”模型：

* **去中心化文件树**: 每个成员都可以将本地的任意目录暴露给当前队伍。软件不会将真实文件推送到网络中，而是仅在内存中生成一层极轻量的“虚拟元数据目录树”（`FileNode`），包含文件名、大小、类型，并在有权限的对方申请查看时实现“秒加载”。
* **按需浏览**: 当其他成员在 UI 中点击展开某个共享文件夹时，才通过 `/parade/browse/1.0.0` 协议流向源节点发起请求拉取下一层级的元数据。这极大地节省了局域网带宽，且能轻松支持十万级以上文件的海量目录共享。
* **fsnotify 实时感知**: 每个共享根自动建立 `fsnotify` watcher，目录内任何变更即时失效树缓存和哈希缓存，下次 `GetLocalTree` 触发重新扫描。
* **绝对所有权**: 成员节点之间完全平等。共享文件的节点即为该目录的唯一服务器，文件修改、删除、共享权限的撤销均在本地瞬间生效，无需全网协商。
* **可控文件接收**: 成员可以自行设定标准，阻断所有大于这个标准大小的文件被直接推入本地并询问是否接收。下载默认路径为 `~/Downloads`。
* **断点续传**: 基于 `ChunkTracker` 双层结构 (bitmap + per-slot maxEnd) 精确追踪每个 slot 的覆盖字节，支持乱序到达和中断恢复，完成后原子重命名 `.parade_tmp → target`。

### 网络通信

“游行”的网络通信基于 **libp2p v0.48.0**，在单一 TCP 端口 4327 上通过 Yamux 多路复用承载全部协议流。

#### 传输栈

| 层级 | 组件 | 作用 |
|------|------|------|
| 传输 | TCP (端口 4327) | 物理连接 |
| 安全 | Noise (XX handshake) | 传输层机密性 + ed25519 身份绑定 |
| 多路复用 | Yamux | 单端口承载多个协议流 |

**身份派生**: libp2p 的 ed25519 密钥由用户的 Curve25519 私钥经 `SHA-256` 确定性派生，确保同一用户在不同设备上具有相同的 libp2p PeerID。

#### 协议流清单

所有协议复用在 TCP 4327 上：

| 协议 ID | 方向 | 数据格式 | 用途 |
|---------|------|----------|------|
| `/parade/identify/1.0.0` | 请求/响应 | JSON `{peer_id, uuid, pubkey}` | 节点身份交换 |
| `/parade/handshake/1.0.0` | 请求/响应 | 加密 nonce 字节流 | 3 阶段连接握手 (Phase 2: 队伍密钥挑战) |
| `/parade/test/1.0.0` | 请求/响应 | `"test"` → 1 字节 ACK | 活性探针 (Phase 3) |
| `/parade/private-chat/1.0.0` | 客户端→服务端 | 4 字节长度前缀 + JSON | 一对一私聊 |
| `/parade/file-meta/1.0.0` | 客户端→服务端 | UTF-8 路径 → JSON | 文件元数据查询 |
| `/parade/file-download/1.0.0` | 客户端→服务端 | JSON 请求 → 流式 JSON `FileChunk` | 可断点续传分块下载 |
| `/parade/browse/1.0.0` | 客户端→服务端 | UTF-8 路径 → JSON `BrowseEntry[]` | 远程目录浏览 |
| `/parade/sync/1.0.0` | 客户端→服务端 | JSON (请求/响应) | 会话历史同步 |
| `parade-chat-<teamHash>` | GossipSub | 加密字节 | 群聊广播 |

**端口 4328**: 启动时在 `4327+1=4328` 端口上运行明文 TCP 识别服务，返回 JSON `{peer_id, uuid, pubkey}`，仅用于节点发现，不承载任何加密流量。

#### 3 阶段连接握手

当用户在前端点击“连接节点”时，串行执行三阶段验证：

1. **Phase 1 — TCP 识别 + libp2p 连接**: 先 dial `ip:4328` 获取对方 PeerID 和公钥，再 `host.Connect` 建立 Noise + Yamux 安全连接
2. **Phase 2 — 队伍密钥挑战**: 通过 `/parade/handshake/1.0.0` 发送 `EncryptTeam(nonce)` 挑战，验证双方持有相同队伍密钥
3. **Phase 3 — 测试消息**: 通过 `/parade/test/1.0.0` 发送 "test" 字符串并等待 ACK，确认端到端通信正常

成功则持久化节点信息到 `./.parade_peers` (JSON, 权限 0600)。

#### 节点持久化与重连

启动时从 `./.parade_peers` 恢复已知节点列表，后台 goroutine 优先用 IP 直连，失败则回退到通过 PeerID 让 libp2p 路由器经其他已知 peer 中转。启动前先将 pubkey 注入 `peerMap`，确保重连前的 `ResolveUUID` 可正常工作。

### 信息存储

既然没有云端服务器，所有的数据沉淀必须在本地完成。“游行”内置了无依赖的纯 Go SQLite 作为本地存储引擎。

* 驱动: `modernc.org/sqlite` (纯 Go，无 CGO)
* 配置: WAL 模式, `busy_timeout=5000ms`, `cache_size=64000KB`, 最大 5 连接
* 8 张核心表: `messages` / `file_logs` / `teams` / `conversations` / `shared_directories` / `share_groups` / `share_group_dirs` / `schema_meta`
* 10 个 Schema 迁移版本，按 Version 升序事务内执行
* 离线可用: 由于数据存储在本地，用户即使断开网络，依然可以打开软件查阅以往的队伍聊天记录和传输日志
* 同步对账机制: 当节点重新连入局域网时，会通过 `/parade/sync/1.0.0` 协议发 `ConvSyncRequest`，根据本地 HLC 游标增量拉取断网期间缺失的消息。事务内批量 `InsertMessageTx` 保证原子性

### 消息时序 — 混合逻辑时钟 (HLC)

由于完全去中心化网络缺乏统一的时间裁判，HLC 完美结合了物理时钟的直观性和逻辑时钟的因果一致性。

**HLC 格式**: `2006-01-02T15:04:05.000Z_<4位计数器>_<NodeUUID前8位>`

例: `2026-06-08T12:30:45.123Z_0042_a1b2c3d4`

* 物理时间: 毫秒精度 UTC，保证大致可读
* 原子计数器: `% 10000`，同毫秒内保证单调不冲突
* 节点前缀: 打破分布式同时性
* **字典序 = 因果序**: `localeCompare` 即可排序，SQLite 索引 `ORDER BY hlc` 无歧义

### 数据加密

“游行”的数据加密模块分三部分：落盘加密、队伍加密、私聊加密。

#### 密钥体系

```
User Password (明文)
     │  + 16B 随机 salt, Argon2id (1轮, 64MB, 4线程)
     ▼
Master Key (32B) ─────── 内存，加密 .parade_identity priv + .parade_teams blob
     │
     ├─→ Curve25519 密钥对 ─→ 私聊 ECDH → SHA-256 → Session Key
     │
     └─→ Team Key (32B, sha256(teamPassword)) ─→ AES-256-GCM 群聊 + 信令
```

| 密钥 | 派生方式 | 存储 | 作用域 |
|------|---------|------|--------|
| Master Key (32B) | `Argon2id(password, salt[16B])` | 内存 | 落盘加密 + 保护私钥 |
| Team Key (32B) | `sha256(teamPassword)` | `.parade_teams` (AES-GCM 加密) | 群聊 + 系统信令 |
| Session Key (32B) | `sha256(ECDH(myPriv, theirPub))` | 内存，每会话 | 私聊双层加密内层 |

#### 三层加密

| 层 | 算法 | 触发时机 | 密钥 |
|----|------|---------|------|
| **传输层** | libp2p Noise (ed25519) | 所有 libp2p 流自动加密 | ed25519 (从 Curve25519 派生) |
| **应用层-队伍** | AES-256-GCM (`EncryptTeam`) | 群聊/私聊出站、握手挑战 | Team Key |
| **应用层-私聊** | Curve25519 ECDH + AES-256-GCM (`EncryptPrivate`) | 私聊双层加密内层 | Session Key |

**私聊双重封装**:

```
raw → EncryptPrivate(raw, peerPubKey) → EncryptTeam(inner) → GossipSub / libp2p stream
```

外层 `EncryptTeam` 让局域网中其他同队节点（即便不是对话目标）也能解密外层信封，从而进行中继/缓存；只有真正的对端才能解开内层。

#### 身份文件 (`.parade_identity`)

```json
{
  "salt": "<16B base64>",
  "encrypted_priv": "<AES-GCM(master, Curve25519 priv)>",
  "pub_key": "<32B base64, 明文>"
}
```

* 权限 `0600`，仅当前用户可读写
* 密码错误时 `LoadIdentity` 返回 `"invalid password"`，没有任何恢复办法
* `personalUUID` 由公钥经 UUIDv5 (SHA-256) 确定性派生，同一密钥对跨设备得到相同 UUID

### 确定性 UUID 派生

四种实体 ID 均通过 UUIDv5 (SHA-256) 从命名空间 + 数据派生，保证跨设备一致：

| 命名空间 | UUID | 用途 |
|---------|------|------|
| `identityNS` | `6ba7b811-...` | 用户身份 UUID |
| `teamNS` | `6ba7b812-...` | 队伍 UUID |
| `conversationNS` | `6ba7b815-...` | 群聊/私聊会话 UUID |
| `shareGroupNS` | `6ba7b814-...` | 共享组 UUID |

**关键性质**: `DerivePrivateConvID(A, B) == DerivePrivateConvID(B, A)`（交换律），Alice 和 Bob 无需协商即可算出同一个会话 ID。

### 日志系统

“游行”内置异步 JSONL 日志代理 (`LogBroker`)，作为正式一等模块：

* 容量: 5000 条环形缓冲，超量后最旧条目被覆盖
* 落盘: 追加模式写入 `./.parade.log`，每条 JSON + `\n`
* UI 实时推送: 通过 `SetCallback` 注册回调，每条日志即时推送前端 `LogPanel`
* 等级: Trace / Debug / Info / Warning / Error
* 源标签: `ipc` / `network` / `file` / `system` 等，前端可按来源过滤
